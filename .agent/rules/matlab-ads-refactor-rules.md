# MATLAB ADS リファクタ共通ルール

MATLAB + ADS + .NET 連携プロジェクトで再利用できる運用ルール。
特定リポジトリに依存しない形で定義し、必要な値はプロジェクト側で差し替える。

## 1) 命名規約（推奨デフォルト）

- パッケージ名: `snake_case`（例: `+twincat_ads`, `+experiment`）
- クラス名: `PascalCase`
- クラスファイル名: クラス名と一致（例: `VirtualMotorService.m`）
- 関数ファイル名: `snake_case`（例: `run_virtualmotor.m`）
- ローカル変数/構造体フィールド/inputParser パラメータ: `snake_case`
- 非公開メソッド・ローカル関数も `snake_case` で統一する

注記:
- 既存公開 API を変更する場合、基本は互換性を無視し、破壊的にリファクタリングを行う。
  - 旧名前空間の再導入禁止
  - README に移行マッピングと破壊的変更点を記載

## 3) 段階的リファクタ手順（汎用）

1. ベースライン取得（現行テスト・実行結果）
2. 新構成を追加（旧構成は残す）
3. 参照を新構成へ切替
4. テスト更新
5. 旧構成削除
6. 残存参照 grep（旧名前空間がコードに残っていないこと）
7. README 進捗更新

## 4) `varargin` 透過ルール

上位 API から `varargin{:}` を下位へ透過する場合:

- 下位 `inputParser` は `KeepUnmatched = true` を使う
- もしくは上位で受理パラメータのみ明示的にフィルタして渡す

目的:
- 上位で有効な引数が下位で「未知パラメータ」エラーになる事故を防ぐ

## 5) ADS アセンブリ解決ルール

外部 .NET 依存の解決順序は明示する:

1. 明示指定引数（例: `ads_assembly`）
2. 既知パス候補
3. アセンブリ名（GAC 等）

失敗時:
- 試行順と失敗理由をエラーメッセージに含める

## 6) テスト実行の共通ブートストラップ

`run_tests.m` を用意し、以下を必須化する:

- `restoredefaultpath`
- `addpath(genpath(<matlab_root>))`
- `testsuite(..., "IncludeSubfolders", true)` 実行

これによりパス依存の不安定さを回避する。

## 7) 検証チェックリスト

最低限:

1. 単体/契約テストが全件 `Passed`
2. 旧名前空間 grep が 0 件（README 等の説明文は除外可）

可能なら追加:

1. 接続確認スモーク（例: ポート列挙）
2. エンドツーエンド実行スモーク（例: 実験ランナー + 可視化）

## 8) ドキュメント更新ルール

- フェーズ更新時に進捗表を更新する
- 結果は絶対日付（YYYY-MM-DD）で記録する
- 失敗時は「原因」と「次アクション」を残す

## 9) この会話から追加した再利用ルール

- 実機スモーク前に、まず自動テストで構文/参照エラーを潰す
- 実機スモーク中に見つかった不具合（引数伝播など）は、その場でルール化して再発防止する
- 大規模移行では README に `Done / In Progress / Next` を残し、途中状態でも判断可能にする

## 10) プロジェクト適用テンプレート

以下の変数は各リポジトリで設定する:

- `<matlab_exe_path>`
- `<repo_root>`
- `<matlab_root>`
- `<deprecated_namespace_pattern>`
- `<smoke_script_1>`, `<smoke_script_2>`
